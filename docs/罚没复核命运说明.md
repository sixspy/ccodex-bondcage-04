# 罚没复核命运说明

> 锁定日：2026-11-22（当日锁死）。本说明是罚没资金命运的唯一正确性口径，
> 代码与页面不得偏离；偏离即记「罚没偏航」并拒写。

## 选定路径：乙路径 —— 复核前笼面零扣

违约核验后的罚没，资金命运只走这一条：

1. **罚没提交 = 只落待复核意图**。`POST /api/forfeits` 写入
   `forfeit_intents`（状态 `待复核`），同一事务内**笼面 `available`、
   笼状态、账户 `frozen`/`balance` 零改**，正式 `forfeits` 册零写。
2. **复核通过 = 原子入册扣款**。复核岗 `POST /api/forfeit-intents/{id}/review`
   （`decision=通过`）在同一事务里：写正式 `forfeits`（`已罚没`）
   + 扣笼 `available` + 减账户 `frozen`/`balance` + 意图晋升（`已晋升`，
   回写 `forfeit_id`）。任一步失败，罚没与扣减整笔同滚，不留半截。
3. **复核驳回 = 意图作废**。意图转 `已作废`，正式罚没册、笼面、
   账户冻结**始终零改**；如需再罚，另起新意图。
4. **复核岗与提交人分人**；复核只能「通过 / 驳回 + 意见」，
   **不得改金额**——意图金额即命运金额。

## 禁止事项

- **禁止第三路**：不存在「先扣后补审」「影子罚没」等任何第三条路；
  甲路径（核验即刻正式扣笼）自本说明锁定之日起废止。
- **禁止混用**：同一笼代不得既走直扣又走意图。混用会出现
  「复核未过钱已出笼」或「复核通过却找不到正式罚没行」的对账假绿。
- **禁止直写**：任何绕过复核、要求直进罚没册的写企图
  （如 `mode=直进罚没册`、复核时夹带改金额），一律记审计
  `罚没偏航` 并以 409 拒写，业务零写。
- **禁止只改文案**：罚没语义以本说明与代码行为为准，页面文案
  只是口径的映射，不得用文案修补行为偏差。

## 并发：同笼抢锁

两人同时罚同一只笼，须抢笼锁 `cage:{id}`：先到者持锁办事，
**后到者只留争用痕**（`contention_log`），不写任何业务行；
同一笼同一时刻只允许一条 `待复核` 意图（库层唯一部分索引兜底）。

## 五页账实同源

罚没页、核验页、入笼页、对账页、审计页同读一套 SQLite 表
（`cages` / `forfeit_intents` / `forfeits` / `attestations` /
`audit_trail` / `contention_log`），库路径 `data/app.db` 不变：

- 对账口径不变：`available + 已拨付 + 已罚没 = 笼总额`（同笼代），
  只认正式册；待复核意图**不计入**，单列展示并互证
  「已晋升意图合计 = 正式册罚没合计」。
- 复核前对账为绿是真绿：钱确实没动；复核后绿也是真绿：
  册、意图、笼面、账户四方同改。

## 事故背景（锁定理由）

旧行为：核验违约后一点罚没，同一提交直写正式罚没册并扣笼减冻，
复核岗未签字钱已出笼，对账公式照样平衡 —— 假绿，出事难撤回。
事故夹具 `scripts/forfeit_false_green_fixture.py` 在本机文件库
复现该假绿（`--expect accident`），并验证本说明生效后的偏航拒写
（`--expect guarded`）。
