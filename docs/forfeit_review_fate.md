# 罚没复核命运说明（2026-11-22 锁死）

## 选定路径：乙（复核通过后入册扣款）

本仓只走乙路径，甲路径与任何第三路径均不采用，也不得与乙路径混用。

| 环节 | 资金命运 | 笼面 / 账户 / 正式罚没册 |
|------|----------|--------------------------|
| 核验违约 | 只把笼置为「核验违约」 | 零改 |
| 罚没写口 | 只建「待复核」意图 | `cages.available`、`bond_accounts.frozen/balance` 零改；正式罚没册零增 |
| 复核通过 | 同一事务入册扣款 | `forfeits` 增一行 `已罚没`；笼可用、账户余额、账户冻结同步扣减 |
| 复核驳回 | 意图置「已驳回」作废 | 三处零改；不自动退款，也不补写正式罚没行 |

## 禁止项

- 甲路径：核验即直入正式罚没册并扣笼，复核仅追加意见。
- 任何第三路径。
- 甲、乙混用（会造成「复核未过钱已出笼」或「复核通过却找不到正式罚没行」）。
- 只改罚没页文案而不改服务写口。

## 偏航处置

任何请求或配置（`FORFEIT_FATE_PATH` 环境变量、请求体 `fate_path` 字段）偏离本说明，
写口一律记审计动作「罚没偏航」并返回 409 拒写；不落任何意图、不扣任何资金。

## 同源核验

- 罚没页：`/api/forfeits` 只列复核通过的正式行；`/api/forfeit-intents` 列意图。
- 核验页：核验行带 `pending_intents` / `formal_forfeits`。
- 入笼页：笼列表带 `pending_intents` / `pending_amount` / `formal_forfeits`。
- 对账页：`/api/reconcile` 的 `forfeited` 只含正式行，待复核意图单列不参与等式。
- 审计页：`/api/audit/forfeit-chain` 校验意图 → 复核 → 正式行链路，并统计偏航次数。

## 并发

同笼罚没与复核均抢 `cage:{id}` 笼锁；后到者只落 `contention_log` 争用痕并返回 409，
不写意图、不写正式行、不改笼面。
