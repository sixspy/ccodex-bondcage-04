## 背景

违约核验后一点罚没就直进罚没册：复核岗还没签字，金额已从笼里抽走，出事难撤回。
罚没必须可复核，且账实不得分裂。正确性口径只此一种，两边不得混用。

## 锁定的写路径（乙）

1. **登记影子**：核验违约后，登记岗 `POST /api/forfeits` 只落影子罚没单（待复核），
   占住意图；笼面可用、账户冻结与余额、正式罚没册一律零改。
   同一只笼同时只允许一张待复核影子单。
2. **换人复核**：复核岗须为具备写权限且非登记人的另一人；复核与登记同人即偏离本纪要。
3. **原子晋升**：复核通过 → 同一事务内写正式罚没册（已罚没）、扣笼可用、
   减账户冻结与余额、记审计、影子单转已晋升；任一环节失败整笔回滚，
   影子作废，正式罚没册与笼面零改。
4. **驳回作废**：复核驳回 → 影子单转已作废，正式罚没册与笼面零改。
5. **晋升失败**：复核时笼状态 / 笼代 / 可用额 / 违约核验任一不再满足 →
   影子作废并拒写，正式罚没册与笼面零改。

## 偏离即偏航

- 任何请求携带非本纪要锁定的口径（如甲路径「立即入罚没册整笔提交」）→
  记审计「罚没偏航」并拒写（409）。
- 复核与登记同人 → 记「罚没偏航」并拒写，影子单保持待复核。
- 禁止只改罚没页文案冒充可复核；口径以 `backend/doctrine.py` 与
  `/api/forfeits/doctrine` 为唯一运行源，页面文案从该源渲染。

## 争用

- 两人同时罚同一只笼：先抢笼锁 `cage:{id}`，后到只留争用痕（contention_log），
  不写任何业务行；争用痕独立提交，业务回滚不丢痕。

## 五页同源

- 罚没页、核验页、入笼页、对账页、审计页共读同一库表：
  影子单不计入「已罚没」合计；对账公式
  `available + released + forfeited == amount`（同笼代）
  在登记、晋升、驳回任一时刻恒成立。
